# ชุดทดลอง CiRA CORE + Python (ภาษาไทย)

ต้นแบบรับผลตรวจจับวัตถุจาก CiRA CORE ผ่าน HTTP แล้วประเมินตำแหน่งจากกรอบภาพ ก่อนพูดข้อมูล/คำเตือนด้วย TTS ภาษาไทยในเครื่อง

## เริ่มใช้งาน

1. แตก ZIP ลงโฟลเดอร์ก่อน อย่ารันไฟล์จากในหน้าต่าง ZIP
2. ติดตั้ง Python 3.12 แบบ 64-bit พร้อม Python Launcher (`py`)
3. เปิดโฟลเดอร์ `CiRA_AutoAlert_Portable` ใน VS Code แล้วรัน `.\run_receiver.bat` หรือดับเบิลคลิก `run_receiver.bat`
4. ครั้งแรกต้องต่ออินเทอร์เน็ต โปรแกรมติดตั้งไลบรารีและดาวน์โหลดโมเดลเสียง Vachana ที่เลือก จากนั้นสร้าง cache ของประโยคที่ใช้ในระบบ อาจใช้เวลาหลายนาที
5. **รอจน Terminal แสดง `TTS พร้อมแล้ว ... ตอนนี้เปิด/รัน Flow ใน CiRA CORE ได้` ก่อน** แล้วจึงเปิด/รัน Flow เพื่อไม่ให้ประโยคเตือนหลุดไปใช้ MP3 ระหว่างเตรียมเสียง
6. Flow ต้องส่งไปที่ `http://127.0.0.1:8765/`; หยุด receiver ด้วย `Ctrl+C`

## ใช้กล้องและลำโพงมือถือ

มือถือส่งภาพเข้าคอมผ่านหน้าเว็บ HTTPS แล้วใช้ Browser Source ใน SplitCam หรือ OBS แสดงภาพ Receiver ก่อนส่งออกเป็น Virtual Camera ให้ CiRA Flow เลือกได้ ไม่ต้องเปิด Camo ระหว่างใช้

ต้องมี SplitCam หรือ OBS Studio และ OpenSSL (ติดตั้งมากับ Git for Windows ได้) บนคอมเพื่อสร้าง HTTPS certificate ในเครื่อง

### ตั้งค่าครั้งแรก

1. ติดตั้ง SplitCam หรือ OBS Studio บนคอม และให้มือถือกับคอมอยู่ Wi-Fi ส่วนตัววงเดียวกัน
2. เปิด receiver แล้วใช้ลิงก์ติดตั้งใบรับรองที่ Terminal แสดง (Android ใช้ไฟล์ `.cer`; iPhone ใช้ลิงก์ profile `.mobileconfig`) ห้ามแชร์ลิงก์ที่มี token หรือไฟล์ `mobile-root-ca.key`
3. ติดตั้งและเชื่อถือ CA ในมือถือ:
   - **Android:** เปิด Settings แล้วค้นหา “Install a certificate” หรือ “CA certificate”; เลือกไฟล์ `cira-autoalert-mobile-root-ca.cer` ที่ดาวน์โหลดมา
   - **iPhone:** เปิดลิงก์ `.mobileconfig` ใน Safari แล้วติดตั้ง profile ที่ Settings > General > VPN & Device Management จากนั้นไปที่ Settings > General > About > Certificate Trust Settings แล้วเปิด full trust ให้ `CiRA AutoAlert Local CA`
4. เพิ่ม Browser/Web Source ใน SplitCam หรือ **Browser Source** ใน OBS โดยตั้ง URL เป็น `http://127.0.0.1:8765/obs-camera` และขนาด 960×540 ตรวจให้ภาพ Receiver แสดงในฉาก แล้วเปิด Virtual Camera ของโปรแกรมนั้น
5. ใน CiRA Flow เปลี่ยน node `WebCam` ให้เลือก **SplitCam (Windows Virtual Camera)** หรือ **OBS Virtual Camera** ตามโปรแกรมที่ใช้ แทน Camo แล้วบันทึก Flow การเลือกอุปกรณ์ทำใน CiRA ด้วยตนเอง ไม่แก้ UUID ของกล้องให้เดาอัตโนมัติ

### ใช้งาน

1. เปิดลิงก์ `หน้าแอป` แบบ `https://...:8766/mobile?...` ที่ Terminal แสดงใน Chrome/Safari และอนุญาตให้เว็บใช้กล้อง
2. กด **เริ่มกล้องและระบบ** ภาพจากกล้องหลังมือถือจะถูกส่งไปคอม; การแตะปุ่มนี้จะอนุญาตให้เบราว์เซอร์เล่นเสียงแจ้งเตือนจาก Receiver บนมือถือ (receiver ยังคงเล่นเสียงบนคอมตามเดิม)
3. กด **หยุดกล้องและระบบ** เพื่อหยุดส่งภาพและปิดกล้องมือถือ

หน้าเว็บต้องเปิดอยู่ด้านหน้าและมือถือไม่ล็อกจอระหว่างใช้งาน; เบราว์เซอร์/ระบบปฏิบัติการอาจหยุดกล้องหรือเสียงเมื่อสลับแอปหรือพักจอ ต้องทดสอบบนรุ่นมือถือจริง ส่วน CiRA/Virtual Camera/receiver ทำงานบนคอม และทั้งสองเครื่องต้องยังเชื่อมต่อ Wi-Fi เดียวกัน

ลิงก์หน้าแอปใช้ token เฉพาะรอบ ห้ามแชร์ และควรอนุญาต Windows Firewall เฉพาะ Private network อย่าใช้ Wi-Fi สาธารณะหรือเปิด port forwarding สู่ Internet ใบรับรองที่สร้างใน `cache/mobile_tls/` ใช้เฉพาะเครือข่ายในบ้าน; อย่าเผยแพร่ private key หรือโฟลเดอร์นี้

ถ้า TTS เตรียมไม่สำเร็จ โปรแกรมจะแสดงว่า session นี้ใช้ MP3 สำรองทั้งรอบ โดยไม่สลับไปมา ให้ตรวจสาเหตุใน `logs/decision_log.jsonl` และ Terminal

## ตั้งชื่อคลาสจากโมเดลเป็นภาษาไทย

ไฟล์ `class_labels_th.json` ใช้แปลชื่อ class ที่ CiRA ส่งมาเป็นคำที่ TTS อ่าน เช่น `bench`/`chair` เป็น “ที่นั่ง” และ `lift`/`elevator` เป็น “ลิฟต์” ถ้าโมเดลส่งชื่ออื่น ให้เพิ่มชื่อ class เป็น key และคำอ่านไทยเป็น value ตัวอย่าง:

คลาส `refrigerator` ถูกตั้งให้พูดว่า “ตู้กดน้ำ” ตามฉากตัวอย่าง แต่เป็นเพียงการเปลี่ยนคำเรียก ไม่ได้เปลี่ยนโมเดลหรือตรวจยืนยันชนิดวัตถุ ดังนั้นวัตถุอื่นที่โมเดลทำนายเป็น `refrigerator` ก็จะถูกเรียกว่า “ตู้กดน้ำ” เช่นกัน

ระบบประกาศเสียงสำหรับทุกคลาสที่ CiRA ส่งมา โดยใช้คำแปลใน `class_labels_th.json` หากยังไม่มีคำแปลจะอ่านชื่อคลาสเดิมจากโมเดล คลาสที่ตรวจจับผิดอาจทำให้มีเสียงแจ้งเตือนผิดพลาดหรือถี่ได้ ส่วน `chair` และ `bench` ยังคงใช้คำพูดรวมว่า “ที่นั่ง”

```json
{
  "lift": "ลิฟต์",
  "bench": "ที่นั่ง",
  "chair": "ที่นั่ง",
  "bathroom": "ห้องน้ำ",
  "men restroom": "ห้องน้ำชาย",
  "women restroom": "ห้องน้ำหญิง",
  "emergency exit": "ทางออกฉุกเฉิน",
  "classroom door": "ประตูห้องเรียน"
}
```

receiver ใช้ชื่อวัตถุ ตำแหน่งกรอบในภาพ และกฎความเสี่ยงที่มีอยู่ มาประกอบเป็นประโยค เช่น “มีลิฟต์อยู่ทางซ้ายมือ” TTS ทำหน้าที่อ่านประโยคนั้น ไม่ได้อนุมานวัตถุใหม่เอง

มี alias ตัวอย่างของห้องน้ำชาย/หญิง ทางหนีไฟ และประตูห้องเรียนเตรียมไว้ในไฟล์แล้ว แต่ต้องตรวจชื่อคลาสจริงที่ CiRA ส่งจากโมเดลที่เทรนเสร็จ แล้วเพิ่มชื่อให้ตรงทุกตัวอักษรใน `class_labels_th.json` (ชื่อ class ใน JSON เป็น key เท่านั้น ไม่ได้เปลี่ยนลำดับ class ID หรือแก้โมเดล)

ตำแหน่งข้อมูลทั่วไปใช้พิกัดเทียบภาพจากกล้อง: ซ้ายเมื่อจุดกลางกรอบอยู่ต่ำกว่า 40% ของความกว้างภาพ, ขวาเมื่อเกิน 60%, ช่วงกลางรายงานเป็นด้านหน้าแทนการเดาซ้าย/ขวา; ติดตามวัตถุและกรองตำแหน่งข้ามเฟรมเพื่อลดอาการสลับด้านจากกรอบสั่น ทั้งนี้เป็นตำแหน่งในภาพ ไม่ใช่การยืนยันว่าทางนั้นปลอดภัย ส่วนการตรวจแนวชนยังใช้พิกัดดิบตามกฎเดิม

สำหรับคลาส `person` ระบบเพิ่มการบอกว่าอยู่ไกล/ระยะปานกลาง/ใกล้ โดยประเมินจากความสูงและพื้นที่กรอบ รวมถึงตำแหน่งขอบล่างในภาพ และทำให้ค่าคงที่ขึ้นต่อ track; เป็นเพียงระดับระยะเชิงภาพ ไม่มีหน่วยเมตร ไม่ใช่เซนเซอร์วัดระยะ และไม่รับประกันระยะจริง หากต้องใช้ระยะที่แม่นขึ้นต้องเพิ่มกล้อง depth/stereo หรือสอบเทียบกล้องกับฉากจริงก่อน

ถ้าโมเดลใหม่ตรวจเฉพาะห้องน้ำ/ประตู/ทางออก/ที่นั่งและไม่มีคลาส `person` ระบบจะไม่มีข้อมูลสำหรับคำบอกระยะคน ต้องคงตัวตรวจจับคนไว้ใน Flow ควบคู่กัน หรือให้โมเดลส่งคลาส `person` มาด้วย

## เลือกเสียงพูด

แก้ `tts_voice.txt` ก่อนเปิดโปรแกรม โดยใส่รหัสเพียงหนึ่งรายการ:

| รหัส | เสียงตามชื่อในโมเดล |
|---|---|
| `th_f_1` | เสียงผู้หญิง 1 |
| `th_m_1` | เสียงผู้ชาย 1 |
| `th_f_2` | เสียงผู้หญิง 2 |
| `th_m_2` | เสียงผู้ชาย 2 |

หยุดแล้วเปิดโปรแกรมใหม่หลังเปลี่ยนเสียง แต่ละเสียงดาวน์โหลดและสร้าง cache แยกกัน การเลือกเสียงอาศัยรหัสที่ผู้เผยแพร่โมเดลระบุ ควรทดลองฟังบนหูฟังของคุณเพื่อเลือกเสียงที่ชอบ

TTS ประมวลผลในเครื่องหลังดาวน์โหลด ไม่ต้องใช้ Azure, API key หรือจ่ายค่าบริการต่อคำพูด การติดตั้ง/ดาวน์โหลดครั้งแรกต้องใช้อินเทอร์เน็ตและพื้นที่ดิสก์ โมเดลมีสัญญาอนุญาต MIT ตาม [model card](https://huggingface.co/VIZINTZOR/VachanaTTS) และโครงการ [VachanaTTS](https://github.com/VYNCX/VachanaTTS2) ทั้งนี้หน้า PyPI ของแพ็กเกจระบุว่ายังไม่มี provenance ยืนยันแหล่งที่มาของการ build จึงควรใช้เป็นต้นแบบและตรวจแพ็กเกจก่อนนำไปใช้จริง

## ระบบเสียงทำงานอย่างไร

- ก่อนเปิดพอร์ตรับภาพ จะสร้าง cache ของประโยคแจ้งเตือนที่ระบบใช้ไว้ล่วงหน้าด้วยเสียงที่เลือก
- session เริ่มด้วย TTS เมื่อ prewarm สำเร็จ; ถ้า TTS ใช้ไม่ได้ตอน warmup หรือระหว่าง session จะล็อกเป็น MP3 สำรองต่อจนจบรอบ และไม่สลับกลับไป TTS จึงไม่สลับไปมารายประโยค
- หลัง warmup การเตือนวัตถุที่ยังไม่มี cache จะถูกเข้าคิวสร้าง; ระหว่างนั้นระบบไม่แทรก MP3 คนละเสียง และจะลองพูดซ้ำจากเฟรมถัดไปเมื่อ cache พร้อม
- หาก TTS ล้มเหลวระหว่าง session จะเปลี่ยนเป็น MP3 สำรองครั้งเดียวและล็อกไว้จนปิดโปรแกรม พร้อมแสดงสาเหตุ
- ระบบตรวจสถานะ pygame mixer และรายชื่ออุปกรณ์เสียงเป็นระยะ; หากอุปกรณ์หลุด/เปลี่ยนหรือช่องเล่นค้าง จะพยายามเปิด mixer ใหม่
- ลดการพูดซ้ำของข้อมูลทั่วไปเป็นทุก 7 วินาที, ข้อมูลคน/ยานพาหนะด้านข้างทุก 20 วินาที และเว้นช่วงเสียงข้อมูลทั่วไปอย่างน้อย 5 วินาที; คำเตือนระดับเข้าใกล้รอให้ประโยคปัจจุบันจบก่อน ส่วนคำเตือนใกล้มาก/ให้หยุดยังแทรกเสียงที่เร่งด่วนน้อยกว่าได้
- เสียง MP3 ใน `audio/` เป็น fallback ทั้ง session เมื่อ TTS ใช้งานไม่ได้ ไม่ใช่ fallback เฉพาะประโยคกลาง session
- ไฟล์ MP3 สำรองตำแหน่งที่นั่งเป็นเสียงอัดเดิมที่พูดว่า “เก้าอี้”; คำว่า “ที่นั่ง” ใช้กับเสียง TTS
- ข้อความประกอบจากคลาส ตำแหน่ง และระดับ heuristic ที่กำหนดใน Python; TTS แปลงข้อความเป็นเสียง ไม่ได้วิเคราะห์ภาพหรือแต่งข้อเท็จจริงเอง
- ข้อมูลทั่วไปอาจสลับสำนวนที่เตรียมไว้แล้ว แต่คำเตือนเร่งด่วนยังใช้ข้อความควบคุมตายตัว
- สถานะ CiRA ขาดเฟรมแสดงใน Terminal ไม่แทรกเป็นเสียงพูด

## ไฟล์หลัก

- `cira_receiver.py` — HTTP receiver, ติดตามวัตถุชั่วคราว, เลือกคำเตือน, TTS และ recovery เสียง
- `tts_voice.txt` — รหัสเสียงปัจจุบัน
- `class_labels_th.json` — mapping ชื่อคลาสจากโมเดลเป็นคำอ่านไทย
- `audio/` — MP3 สำรอง
- `flow/SmartVision_Project_447_AUTO_ALERT_FIXED.flow` — flow CiRA CORE
- `model/v4/` — โมเดลตรวจจับที่ flow ใช้
- `cache/tts/` และ `cache/vachana/` — เสียงที่สร้างและโมเดลในเครื่อง ไม่รวมใน ZIP
- `logs/decision_log.jsonl` — log การเลือกเสียงและข้อผิดพลาด

## ข้อจำกัด

- การเปลี่ยน TTS/เสียงพูดไม่ได้เพิ่มความแม่นของการตรวจจับหรือวัดระยะ
- ตำแหน่งและการเข้าใกล้เป็นการประมาณจากกรอบภาพ ไม่ใช่ระยะจริงเป็นเมตร
- กล้องเดี่ยวและ heuristic นี้ยังไม่ใช่อุปกรณ์นำทางหรือระบบความปลอดภัยที่ผ่านการรับรอง
- คำถามที่พิมพ์เกี่ยวกับตำแหน่งที่นั่งยังเป็นฟีเจอร์ทดลอง; ยังไม่มี LLM/voice assistant อิสระ
- การกู้คืนอุปกรณ์เสียงพยายามลดโอกาสเงียบ แต่ต้องทดสอบกับหูฟังและคอมพิวเตอร์จริงก่อนสาธิต
